# v5.30.4 自动唤醒修复

本机四个相关开关全部开启，但最近自动唤醒结果为“最小请求未完成，本周期不再自动尝试”。通过安装在本机的 Codex CLI 0.152.1 和仅监听 127.0.0.1 的模拟 Responses 接口复现：原启动参数包含 `model_providers.openai.request_max_retries=0` 与 `model_providers.openai.stream_max_retries=0`，CLI 以退出码 1 拒绝启动，原因是 `openai` 为不可覆盖的内置服务 ID。模拟接口未收到任何请求。

已删除这两项无效覆盖。此前针对 Windows 沙箱的推测性 `windows.sandbox="elevated"` 修改也已撤回；最终参数继续使用只读沙箱、临时空目录、临时会话、关闭工具与插件，不携带当前聊天或项目指令。

请求现在使用 CLI JSON 事件核验完成状态。仅进程退出码为 0 且出现 `turn.completed` 才显示完成；即使进程退出码为 0，收到失败事件也不会误报成功。失败结果保留退出码、模型与简短错误原因；密钥、Bearer 内容、邮箱与本机路径会被脱敏，保存在既有本地用户数据内。

按照 [OpenAI 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 将本次唤醒进程的技能目录上下文预算设为 1，以降低自动唤醒附带的目录输入。本机模拟请求体从 44,271 字节减少为 22,412 字节；此数值是 HTTP 请求体字节数，不是 token 计费统计，仍存在模型系统提示开销。

每周期一次的限制及持久化去重继续生效；不会清除已经尝试过的记录或重试当前周期。必须先后两次确认同一账户的额度恢复，才会尝试一次最小请求；请求完成后仍以随后官方返回的重置时间为准。

验证结果：

- 修复前：本机 CLI 退出码 1，模拟接口接收请求 0 次。
- 修复后：同一份 CLI 退出码 0，模拟接口接收请求 1 次，收到 `turn.completed`。
- 额度生命周期与失败诊断：48 项通过，包含非零退出、退出码为零但请求失败、脱敏、去重与重启行为。
- 原生界面：21 项通过，包含开关持久化、错误原因刷新显示和页面滚动。
- 以上验证不使用真实账号发送模型请求，不消耗真实额度。官方服务真实恢复时的执行仍需下一次周期核验。

发布包保留原角色素材，个人设置仍位于 `%LOCALAPPDATA%\ConanDesktopAssistant`，不包含在 ZIP 内。先从托盘退出旧版，再打开新版 EXE 或快捷方式，避免同名单实例继续激活旧版。
